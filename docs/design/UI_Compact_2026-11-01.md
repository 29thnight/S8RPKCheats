# 작은 편집 창, 분류 목록과 최소화 아이콘

## 목적과 분석 범위

창과 버튼 사이의 공백을 줄이고, 사용자 제공 Victoria 예제 스크린샷처럼 왼쪽
분류를 연속된 세로 목록으로 구성한다. 최소화 상태에서는 작은 아이콘만 남기고,
아이콘을 클릭하면 이전 편집 화면을 복원하는 동작을 목표로 한다.

아래는 추가 atlas 8장과 참조 스크린샷을 직접 확인한 분석 및 적용 내용이다.
파일명에 포함된 숫자는 이미지의 공식 용도나 상태를 증명하지 않는다. 버튼의
normal/hover/pressed/disabled 매핑은 외관을 보고 이번 UI에 지정한 것이다.
이 문서의 리소스 분석은 구현·빌드·게임 내 동작 검증을 대신하지 않는다.

## 채택 영역

좌표는 원본 픽셀의 **`[left, top, right, bottom)`**이다. 이미지 크기는 위 표를
따르며, normalized UV를 계산할 때 두 atlas의 크기를 혼동하지 않는다.

| Atlas | 용도·상태 | 영역 | 크기 |
|---|---|---|---|
| `compact_controls` | 기본 버튼 | `(1760, 82, 1865, 116)` | 105 × 34 |
| 동일 | hover 버튼 | `(1867, 82, 1972, 116)` | 105 × 34 |
| 동일 | 눌린 버튼 | `(1502, 86, 1607, 120)` | 105 × 34 |
| 동일 | 비활성 버튼 | `(1609, 106, 1714, 139)` | 105 × 33 |
| `navigation_controls` | 최소화 목록 아이콘 기본 | `(787, 111, 849, 159)` | 62 × 48 |
| 동일 | 최소화 목록 아이콘 hover | `(853, 111, 915, 159)` | 62 × 48 |
| 동일 | 최소화 목록 아이콘 눌림 | `(919, 111, 981, 159)` | 62 × 48 |
| 동일 | 최소화 목록 아이콘 비활성 | `(655, 123, 717, 171)` | 62 × 48 |
| 동일 | 선택 분류 행의 적갈색 문양 | `(592, 174, 992, 222)` | 400 × 48 |

선택 분류 행에는 문양 strip과 얇은 금색 테두리를 조합한다. 대체 후보인
`(130, 68, 630, 117)`의 적갈색 붓칠 strip은 가장자리가 불규칙하므로 정돈된
목록에는 채택하지 않는다. 최소화 아이콘은 목록을 여는 의미의 glyph를 고른
것이며, 첨부 스크린샷에 없는 원본 모드의 최소화 디자인을 복제한 것은 아니다.

## 투명도와 표시

8개 atlas는 모두 RGBA다. 검게 보이는 빈 영역은 알파 0이며 부분 투명 픽셀도
포함한다. **검정 color-key 제거를 하지 않고 원본 알파를 유지한다.** 선택 행의
문양 strip `(592, 174, 992, 222)`은 전체 영역의 알파가 255다.

작은 버튼의 모서리는 기존 nine-slice 방식으로 보존한다. 서로 가까운 sprite가
섞이지 않도록 바깥 UV의 0.5픽셀 inset을 유지하고, 내부 slice 경계는 공유한다.
최소화 아이콘은 원래 종횡비를 유지한다. 이미지의 투명 테두리가 클릭 불가능한
틈을 만들지 않도록 버튼 전체를 하나의 ImGui 조작 영역으로 취급한다.

## Victoria 참조의 해석과 배치 기준

`image(20261101-033537).png`는 1083 × 502이며 왼쪽 분류 영역은 약 220픽셀,
9개 행은 각각 약 54픽셀 높이다. 비선택 행은 공유 갈색 배경 위에 있고 개별
버튼 테두리가 없다. 선택 행에만 적갈색 바탕과 얇은 금색 테두리가 표시된다.

이번 배치 기준은 **분류 폭 170픽셀, 행 높이 34픽셀**이다. 각 행 전체를 클릭할
수 있게 하고, 선택 행만 강조한다. 일반 버튼·표·child의 간격도 함께 줄여
버튼 높이만 작아지고 여백은 남는 결과를 피한다. 100% 배율의 기본 창은
**1100 × 790 → 900 × 620**, 최소 크기는 **640 × 420**으로 변경했다.
본문 버튼은 42픽셀에서 30픽셀로 줄였고, 전역 세로 항목 간격은 8픽셀에서
4픽셀로 줄였다. 본문 padding은 18 × 16에서 10 × 8로 줄였다.

최소화 동작의 확인 기준은 다음과 같다.

- 메인 창의 제목 표시줄도 숨기고 36픽셀 클릭 영역의 작은 목록 아이콘을 표시한다.
- 이미 별도로 연 편집창은 독립적으로 사용하며, 알림·무장 바로가기는 아이콘 우클릭에 모은다.
- 아이콘 밖을 클릭해도 편집 창이 복원되지 않는다.
- 아이콘 클릭으로 복원하면 직전 분류와 편집 상태를 유지한다.
- 작은 화면이나 배율 변경 후에도 아이콘이 작업 영역 밖으로 나가지 않는다.

기본 최소화 버튼, 제목 표시줄 접기, X, 백틱과 AutoLoadMenu 모두 같은 최소화
상태를 사용한다. 팝업 편집 중 백틱은 팝업이 닫힌 후 처리한다. 최소화 중에는
메인 창의 Begin을 호출하지 않으므로 숨겨진 큰 창이 마우스를 가로채지 않는다.
기본 리소스가 없어도 분류 행과 아이콘은 동일 ID의 ImGui 컨트롤로 동작한다.

`menu_sprites.h`의 작은 위젯, `feature_menu.cpp`의 창·분류·최소화, `overlay_present.cpp`의
백틱 입력과 보조 위젯 경로를 변경했다. UI·서비스 CPU 이미지·DX11 SRV 배열을
5칸으로 맞추고 리소스 304/305를 추가했다. 미리보기에서도 같은 atlas 순서와
`request_feature_menu_toggle`을 사용한다.

## 검증 결과

| 항목 | 결과 |
|---|---|
| Linux 독립 미리보기 | GCC 13.3 Debug 빌드 및 실제 ImGui 실행 성공 |
| SDL 입력·상태 검증 | 18개 사례, 167개 검사 통과; 100%/125%/150%, 타이틀/로딩/오류/외부 관리, atlas 누락 포함 |
| 이미지 검사 | Linux 검증 PNG 44장, PNG 청크·CRC 검사 통과 |
| 공용 sprite 위젯 | 액션 버튼·분류 행·아이콘의 마우스/키보드/비활성/fallback ID/UV/스타일 복원 CTest 통과 |
| Windows x64 미리보기 | MinGW 13.0 Release 링크 성공; Wine64 + Xvfb에서 최소화·복원 28개 검사, 107프레임 실행 및 PNG 4장 생성 |
| DLL 리소스 | 리소스 301–305를 포함한 `resources.rc`의 Windows COFF 리소스 컴파일 성공 |

최소화 검사는 작은 버튼, 네이티브 접기·X, 백틱을 실제 SDL 이벤트로 누른다.
아이콘을 클릭해 복원했을 때 이전 분류와 창 위치·크기가 유지되며, 숨긴 메인
창이 마우스를 가로채지 않는지 확인한다. 640 × 480으로 줄인 화면과 150%
배율, atlas가 없는 상태도 검사한다. 자동 시작은 `AutoLoadMenu` 설정을 통해
실제 `update_feature_menu` 경로를 사용한다. 모달 중 최소화 지연도 확인했다.

150% 화면의 알림 속도 레이블 잘림을 발견해 슬라이더 폭을 남은 열 공간에
맞추었다. 125%/150%에서 ItemAdd 당시의 열 clip 영역과 전체 항목 경계를
대조하는 검사로 수정 결과를 확인했다.

게임에서 쓰는 메뉴·스프라이트 소스를 미리보기에서도 직접 컴파일했다. 이번
검증에는 실제 게임 프로세스, 게임 메모리 쓰기, DX11 주입 실행과 전체 게임
DLL의 MSVC 빌드는 포함되지 않는다. Wine 실행은 실제 Windows PC 검증과 구분한다.

재컴파일 범위는 변경한 overlay 단위와 `feature_menu.h`, `ui_atlas.h`,
`ui_bridge.h`, `dx11_overlay.h`에 의존하는 overlay/services/runtime 단위다.
프록시 타깃은 PNG 리소스를 다시 컴파일·링크해야 한다. 독립 미리보기는 변경된
공유 UI와 preview 단위를 다시 컴파일한다.
