## 다음 단계에서 먼저 사용할 구분

1. P1은 평가된 프로젝트 항목을 출발점으로 삼되, 빌드가 허용된 뒤 실제 명령·전처리·링크·배포 결과를 별도로 기록한다.
2. P2 이후는 기능 보존표의 기존 동작을 기준으로 사용하고, 문서에 `미확인`으로 표시된 주소 수명·실행 경로를 보장된 계약으로 간주하지 않는다.
3. P4·P7·P8의 worker와 hook 이관은 정적 설치 주체와 실제 callback 실행 스레드, 해제 호출과 실행 완료를 구분한다.
4. 자산은 확인된 파일과 고지를 보존하고, 확인하지 못한 출처를 임의로 확정하지 않는다.

설계의 P0 통과 조건 전체는 위 미확인 항목 때문에 아직 증명되지 않았다. 빌드 금지 지시에 따라 실제 빌드를 수행하지 않았고, 게임도 실행하지 않았다. 상세 근거와 기존 조사 이력은 [P0 점검표](P0_Audit.md)를 따른다.

## 새 런타임 연결 상태

현재 `src/proxy/entry.cpp`의 `DllMain`은 모듈 주소와 종료 요청만 기록한다. 세 프록시 프로젝트는 런타임 프로젝트를 참조하지만 `start_runtime_services`를 호출하는 경로가 없어 Present hook과 설정 서비스는 시작되지 않는다. 입력용 `install_window_subclass`도 호출하는 곳이 없다.

`tick_game`의 호출은 `run_game_loop`에만 있으며, 그 루프는 게임이 소유한 것으로 확인된 콜백이 아니라 자체 스레드용 반복문이다. `commit_ui_commands` 역시 호출하는 곳이 없어 화면 명령이 처리되지 않는다. 따라서 단순히 이 루프를 시작하거나 Present에 직접 연결하면 게임 메모리의 소유 문맥을 요구하는 설계와 맞지 않는다.

연결 전에 해결할 항목은 다음과 같다.

1. loader lock 밖에서 프록시의 초기화가 시작되는 경로와 DLL 참조 수명을 정한다. DXGI factory export만으로는 직접 전달되는 HID·DInput export를 사용하는 구성을 포괄하지 못한다.
2. 게임이 호출하는 갱신 지점과 스레드 소유권을 확인하고, 그 문맥에서 `tick_game`과 `commit_ui_commands`가 순차 실행되도록 한다. 확인 전 자체 반복문이나 Present를 게임 실행 지점으로 취급하지 않는다.
3. 설정 파일 읽기와 현재 `apply_config`가 사용하는 설정 해석은 설정 서비스에서 수행하고 결과를 게임 명령 처리에 전달하도록 분리했다. `tick_game`의 모듈 이미지 탐색은 게임 콜백 밖으로 옮겨야 한다.
4. 창 소유 스레드에서 subclass를 설치·해제하고, Present 및 입력 콜백 종료를 확인한 뒤 렌더 자원을 해당 소유 문맥에서 정리한다. 현재 `finish_overlay_stop`의 호출자는 이런 완료를 제공하지 않는다.

이는 현재 소스의 정적 연결 상태다. 실제 진입점, 콜백 스레드와 종료 동작은 빌드나 실행으로 확인하지 않았다.
