# P0 실행 경로와 기능 이관 조사

기준 소스: `reference/S8RPKCheats`, 커밋 `068ca1d881edf870f7cf06f935cf50e286004af8`. 이 문서는 정적 조사 기록이다. 전체 기능의 실행 스레드와 패치 소유권은 아직 확인하지 않았다. 빌드 입력은 [별도 목록](P0_Build_Inputs.md)에 기록한다.

설계 P0 요구별 자료와 미확인 범위는 [P0 인계표](P0_Handoff.md)에서 확인한다.

## 확인한 실행 경로

| 경로 | 현재 동작 | 이관 시 보존할 계약 |
|---|---|---|
| `dllmain_hid.cpp` | hid export를 시스템 DLL로 포워딩하고 process attach에서 초기화 스레드를 만든다. detach에서 Shutdown을 호출한다. | 프록시 export와 시작·종료 경계를 별도로 확인한다. |
| `Source.cpp`, `Source_impl.inc` | 조기 로그와 책략 UI 준비 후 게임 초기화를 시도한다. 실패 시 별도 스레드에서 최대 60회, 약 500ms 간격으로 재시도한다. | 책략 UI의 조기 준비와 게임 데이터 준비 후 설정 적용의 순서를 구분한다. 매크로 치환은 명시적 호출로 교체한다. |
| `Source_impl.inc` | ClientBGThread가 `Menu::Loops`를 30ms 간격으로 호출하고, MainThread도 30ms 간격으로 메뉴 키를 확인한다. 정상 종료에서 두 worker를 join한다. | 기능별 안전한 게임 접근 문맥을 확인한 후 조정 루프로 옮긴다. |
| `Source_impl.inc`, `Engine.cpp` | 입력 API와 D3D 훅을 설치하고 전체 훅 활성화·비활성화 경로를 사용한다. 종료 경로가 정상 종료와 프로세스 종료를 구분한다. | 훅별 소유자, 원본 함수 수명, callback 종료와 해제 순서를 확인한다. |
| `Config.cpp`, `ConfigBase.inc`, `Menu_impl.inc` | 설정 wrapper가 기본 저장·로드를 호출하고 추가 필드를 별도로 처리한다. 일반 설정 적용은 게임 데이터 준비까지 지연된다. | 기존 설정의 키·기본값·적용 시점과 저장 호환성을 필드별로 확인한다. |
| `Resources.rc` | 범위 이미지 11개와 effect/speciality 기본 JSON을 포함한다. | 리소스 ID와 실제 데이터의 호환성을 유지한다. |

## 기능 보존 범위

| 기존 구성 | 확인한 범위 | 다음 조사 |
|---|---|---|
| `Cheats/Civilian` | 도시·내정·임무·주점 관련 기능 | 각 설정, 패치와 갱신 시점 |
| `Cheats/Officer` | 무장 목록·편집·성장·기재·관계 | 게임 세대, 값 범위, 기재 6개 효과 슬롯과 데이터 출처 |
| `Cheats/Social` | 대화·선물·관계·임신 등 | 각 활성화 경로와 원상 복구 |
| `Cheats/War` | 전투·포획·책략·공성·AI 관련 기능 | 설치 대상과 전투 객체 수명, 패치 복구 |
| `Cheats/System` | 배속·월·기술·시작 설정 등 | 시간 훅 원본 경로와 worker 종료 |
| 메뉴·오버레이 | 기능별 메뉴, DX11/Win32 ImGui 및 이미지 | 입력 캡처, 한글 IME, DPI, resize와 장치 수명 |

위는 소스 분류이며 기능별 동작 확인을 완료한 목록이 아니다. props에서 추가되는 `RulerTransferProposal` 두 소스도 조사 대상이다.

## 이관 시작

`src/domain/trait.h`에 기존 `OfficerData.h`의 `TalentEffect`와 `TalentInfo`에 대응하는 값 구조를 분리했다. 효과 ID와 두 값은 각각 16비트이며 기재당 효과 슬롯은 6개다. 기존 읽기·쓰기 함수에는 연결하지 않았고, 바이너리 레이아웃이나 직렬화 형식으로 사용하지 않는다.

## 남은 P0 작업

- 12개 구성의 프로젝트 평가와 링크 후보는 [빌드 입력](P0_Build_Inputs.md)에 기록했다. 실제 전처리·링크·배포 입력은 빌드하지 않아 확정하지 못했다.
- 설정 키와 기본값의 정적 목록은 [설정 계약](P0_Config.md)에 기록했다. 기능별 설치·해제·게임 객체 수명과 실제 실행 스레드는 계속 확인한다.
- 매크로·worker·MinHook 대상과 직접 패치의 정적 목록을 보강했다. 조건부 경로, 모든 패치의 소유·복구, 콜백 수명과 일부 원본 출처는 미확인이다.
- [기능 보존표](P0_Feature_Contracts.md)의 주요 실행 경로와 회귀 조건을 전체 기능으로 확장하고 원본과 대조한다. 현 단계는 P0 완료가 아니다.

## 메뉴 열과 기능 진입점

`Menu_impl.inc:723-746`은 메뉴가 펼쳐지고 `gameBase`가 유효하며 메인 표 생성이 성공했을 때 세 열을 순서대로 호출한다. `MainColumn1.cpp`는 내정·시나리오·무장 상세, `MainColumn2.cpp`는 평정·무장 편집, `MainColumn3.cpp`는 자녀 이름 동기화 후 교류·전쟁 섹션을 호출한다. 각 호출은 같은 메뉴 그리기 경로의 순서이며 실제 Present 스레드 ID는 확인하지 않았다. 자녀 이름 동기화의 주기와 공유 맵은 [무장 조사](P0_Officer.md)에 기록했다.

x64 구성의 평가된 컴파일 항목 중 `Cheats`, ImGui, MinHook, Kiero 경로를 제외한 파일명을 기능별 P0 문서에서 대조했을 때 `MainColumn1.cpp`, `MainColumn2.cpp`, `pch.cpp`가 정확한 파일명으로 검색되지 않았다. 앞의 두 파일의 직접 호출은 위에 연결했다. `pch.cpp`는 공통 헤더 컴파일 입력이다. 이전 대조에서 `SkillCountManager.cpp`도 포함한 것은 상대 경로의 시작 부분 `Cheats\`를 제외하지 못한 오류였으며, 이 파일은 `Cheats\System`에 있다. 파일명 검색은 각 파일의 모든 조건부 경로를 확인했다는 뜻이 아니다.

`MenuSectionsCouncil.cpp`는 컴파일 입력이지만 그 `DrawCouncilSection`은 기준 자체 cpp·h·inc 직접 검색에서 선언과 정의 외 호출을 찾지 못했다. 현재 메인 두 번째 열은 `DrawCompactCouncilSection`을 호출하고 그 구현은 `CouncilCompactSection.h`의 매크로 wrapper를 거쳐 `CouncilCompactSectionBase.h`에서 포함된다. 두 평정 메뉴 구현에 비슷한 조작이 있어도 컴파일 입력만으로 두 메뉴가 모두 화면에 표시된다고 판단하지 않는다. 간접·외부 호출과 실제 렌더는 확인하지 않았다.

두 평정 구현의 같은 줄에 있는 `ImGui::Checkbox`, `Button`, `InputInt`와 `u8` 문자열 리터럴을 비교하면, 압축 구현에는 `도시 이동 후 평정 지속`, `부하의 군주 이동 제안`, `세력 도시 재야 무장 처단`이 추가로 나온다. `단절 영토 무장 이동 제한`은 비호출 후보의 본문에 직접 있고, 활성 압축 구현에는 `CouncilCompactSection.h`의 유목기병 체크 wrapper가 삽입한다. 이 비교는 같은 줄의 해당 호출만 대상으로 하며 다중 행·다른 조작·매크로 전개와 기능별 동작의 완전 비교는 아니다. 세 기능의 setter·저장·실패 경로는 [기능 보존표](P0_Feature_Contracts.md)를 따른다.
