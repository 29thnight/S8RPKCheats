# C# Native AOT 외부 모드 연구 메모

작성일: 2026-11-02  
대상: SAM8REPKCheat / 삼국지8 REMAKE with 파워업키트  
상태: 연구 방향 기록. C# 모드 로더와 SDK는 아직 구현하지 않음.

## 목표

모드 작성자는 C#으로 기능을 작성하고 Native AOT로 빌드한 DLL을 배포한다. 사용자는 게임의 `Mods` 폴더에 DLL을 넣는다. 현재 C++ DLL은 게임 내부 함수·데이터·UI와 모드 사이의 연결을 담당한다.

모드마다 게임 메모리 주소와 후킹 코드를 다시 작성하지 않고, 공통 SDK를 통해 다음 기능을 사용할 수 있게 하는 것이 목표다.

- 게임 메뉴에 버튼을 추가하고 클릭 이벤트를 받는다.
- 무장·도시 등의 상태를 조회하고 기존 편집 기능을 호출한다.
- 턴 시작·전투 종료 등 게임 이벤트에 동작을 연결한다.
- 분석된 계산 지점에 한해 피해량·보상·AI 판단 등의 규칙을 확장한다.

게임 전체 내부 로직이 자동으로 C#에 노출되는 것은 아니다. 분석해서 연결한 기능부터 모드 API로 제공한다.

## 이번 대화에서 확인한 내용

### 게임 자체 UI 버튼과 ImGui 연결

`src/overlay/feature_menu.cpp`에 시작메뉴 → 편집 화면용 네이티브 버튼 테스트를 구현했다.

1. `EditUIMainLayout`의 기존 컨트롤 정의 6개(배경 1개, 버튼 5개)를 복사한다.
2. 게임 컨트롤 생성 경로에 `치트 편집` 버튼 정의를 추가한다.
3. 게임이 새 버튼을 생성·등록하고 기존 그룹과 함께 관리한다.
4. 기존 편집 버튼의 클릭 처리에서 새 항목 인덱스 6만 분기한다.
5. 클릭은 atomic 플래그로 전달하고, ImGui 렌더링 쪽에서 편집기를 연다.

사용자가 실제 게임에서 버튼 클릭 후 ImGui 편집기가 열리는 것을 확인했다. 따라서 **게임 자체 UI의 이벤트를 외부 기능에 연결하는 작은 사례는 동작 확인이 끝났다.**

그 후 흰색 배경을 한 행 늘리고 새 버튼을 기존 버튼과 같은 간격으로 정렬하도록 수정했다. 정렬 수정본은 Release 빌드 및 게임 폴더 DLL 교체까지 완료했으며, 수정 후 화면은 이 메모 작성 시점에 확인하지 않았다.

현재 테스트 버튼은 게임의 기존 금색 버튼을 사용한다. 앞서 요청한 붉은 버튼 스타일은 네이티브 버튼에 아직 적용하지 않았다.

### 기존 코드에서 재사용할 부분

| 위치 | 역할 / 연구 시 활용 |
|---|---|
| `src/overlay/feature_menu.cpp` | `NativeEditControl`, `native_edit_controls`, `native_edit_clicked`: 네이티브 UI 생성과 클릭 연결 사례 |
| `src/domain/commands.h` | 현재 편집 기능의 명령 정의. 모드 API의 초기 기능 목록 후보 |
| `src/services/command_mailbox.h` | 명령 제출·처리·완료 결과 전달 구조 |
| `src/runtime/command_commit.cpp` | 기존 명령 적용 및 게임 상태에 따른 처리 조건 |
| `src/runtime/game_loop.cpp` | 런타임 실행 흐름과 DLL 수명 관리 확인 지점 |
| `src/platform/windows/hook.h` | 현재 후킹 계층 |

기존 명령 처리 경로를 재사용하되, 모든 명령이 게임 UI 스레드에서 실행된다고 가정하면 안 된다. API별 호출 스레드와 반영 시점을 확인해야 한다.

### 분석한 실행 파일의 내부 경로

아래 주소는 모듈 기준 RVA이며, 현재 분석한 실행 파일에만 해당한다. 모드에는 주소를 노출하지 않고 C++ 연결 계층 안에서 관리한다.

| 항목 | RVA |
|---|---|
| `EditUIMainLayout` vtable | `0x271EB28` |
| 컨트롤 정의 그룹 생성 함수 — 실제 테스트에서 후킹 | `0x1D13E60` |
| 편집 메뉴 클릭 콜백 — 실제 테스트에서 후킹 | `0x76EC40` |
| `CmnButton` 생성자 | `0x1694A10` |
| 버튼 초기화 경로 | `0x16945C0` |
| 부모 레이아웃 연결 | `0x1751A0` |
| 이벤트 콜백 등록 | `0xEF40` |
| 버튼 크기 조정 | `0x1631D70` |
| 객체 해제 경로 | `0x15BA0` |

현재 코드의 실행 파일 식별값: PE timestamp `0x69A67ED1`, image size `0x440F000`. 게임 업데이트 시 다시 확인한다. 개별 내부 함수의 임의 호출을 모두 실행 검증한 것은 아니며, 실제 테스트는 기존 그룹 생성·클릭 경로를 이용했다.

## Native AOT를 사용하는 배포 구조

```text
SAN8R/
  HID.dll                  # C++ 게임 연결 계층 + 향후 모드 로더
  Mods/
    ExampleMod.dll         # C#을 win-x64 Native AOT로 빌드한 모드
```

Native AOT로 게시한 클래스 라이브러리는 네이티브 DLL로 사용할 수 있다. 필요한 런타임 코드가 포함되므로 사용자 PC에 별도 .NET 설치나 `hostfxr` 호스팅이 필요하지 않다. 추가 자산이나 외부 네이티브 라이브러리가 없는 모드는 DLL 하나로 배포할 수 있다.

C++ 로더는 `LoadLibraryExW` 등으로 DLL을 로드하고, `GetProcAddress`로 약속된 진입 함수를 찾는 구조를 검토한다. C#에서는 `UnmanagedCallersOnly`의 `EntryPoint`로 진입 함수를 내보낸다.

일반 .NET 어셈블리를 `Assembly.Load`로 읽는 구조와 구별해야 한다. Native AOT의 관리 어셈블리 동적 로딩 제한은 C++ 로더가 이미 네이티브로 컴파일된 모드 DLL을 읽는 것과 다른 문제다.

## 제안하는 모드 API 경계

다음은 설계안이며 현재 존재하는 API가 아니다.

```text
C# 모드 / SDK
    ↕ C ABI: 고정 폭 값·구조체·함수 포인터·불투명 핸들
C++ 모드 호스트
    ↕ 기존 명령 처리 / 상태 조회 / 게임 스레드 이벤트
게임 내부 함수·데이터·UI
```

- 초기화 진입 함수는 `ModInitialize`처럼 고정된 이름으로 둔다.
- 호스트가 API 버전, 구조체 크기, 컨텍스트 핸들, 기능 함수 포인터를 전달한다.
- SDK 안에서는 편리한 C# 클래스를 제공하되 경계에는 관리 객체나 C++ STL 타입을 넘기지 않는다.
- 문자열 인코딩, 버퍼 크기, 할당·해제 주체를 정한다. 게임 UI 문자열은 이번 분석에서 UTF-16 사용을 확인했다.
- 게임 객체 포인터 대신 ID와 세션 세대를 포함한 핸들을 사용해 로드 전후 객체 수명을 구분한다.
- 모드가 만든 구독·버튼·작업은 모드별로 추적하고 비활성화 시 해제한다.
- 바깥에서 들어온 데이터는 API 입구에서 한 번 확인하고, 검증된 내부 값은 중복 검증하지 않는다.
- C# 예외를 네이티브 호출 경계 밖으로 넘기지 않도록 실패 전달 규약을 정한다.

읽기 API, 변경 명령, 즉시 결과가 필요한 규칙 콜백은 실행 방식이 다르다.

| 종류 | 제안 방식 |
|---|---|
| 상태 조회 | 일관된 스냅샷 또는 명시된 스레드에서 조회 |
| 편집·UI 생성 요청 | 명령으로 제출하고 해당 작업의 소유 스레드에서 처리, 완료 결과 전달 |
| 피해량 등 즉시 반환값이 필요한 계산 | 해당 게임 함수 안에서 동기 호출. 후킹 지점과 인자·반환값을 개별 분석 |

고빈도 계산 콜백은 호출 시간과 할당량을 측정한다. GC가 있는 C# 모드이므로 AOT만으로 실행 시간이 일정해지는 것은 아니다.

## 첫 실험 범위

첫 단계는 게임 규칙 변경까지 넓히지 않고, 이미 확인한 UI 경로로 C# ↔ C++ 왕복을 검증한다.

1. C# 클래스 라이브러리를 `win-x64` Native AOT DLL로 게시한다.
2. 호스트에서 모드 초기화 진입 함수를 호출한다.
3. 모드가 SDK를 통해 시작메뉴 → 편집 화면에 버튼 하나를 등록한다.
4. 게임 버튼 클릭이 C# 콜백으로 전달된다.
5. C# 콜백이 호스트 API로 기존 ImGui 편집기를 연다.
6. 편집 화면을 나갔다가 다시 들어가도 버튼이 중복 생성되지 않는지 확인한다.
7. 모드 비활성화 후 콜백·작업·UI가 남지 않는지 확인한다.
8. 해상도와 창모드 변경에서도 게임 레이아웃 정렬과 클릭 영역을 확인한다.

이후 기존 무장 조회·편집 명령을 하나 연결하고, 다음 단계에서 턴 이벤트를 추가한다. 피해량·AI 규칙 변경은 별도 분석 대상으로 둔다.

## DLL 수명과 모드 갱신

Microsoft 문서상 Native AOT 라이브러리의 `FreeLibrary` 언로드는 지원되지 않는다. 초기 설계는 **게임 시작 시 로드, DLL 갱신은 게임 재시작 후 적용**을 기준으로 한다.

모드 비활성화는 DLL 언로드와 구별한다. 이벤트 구독 해제, 대기 작업 취소, UI 제거로 기능을 끌 수 있지만 DLL 자체는 프로세스에 남긴다. 각 모드 사이에는 관리 객체를 직접 공유하지 않는다.

실행 중 `.cs` 파일을 수정해서 즉시 반영하는 스크립팅은 이번 Native AOT 배포안의 목표에 포함하지 않는다. 필요해지면 별도 관리 런타임 호스팅 방식과 비교한다.

## 추가로 확인할 것

- 여러 Native AOT 모드 DLL을 동시에 로드했을 때의 메모리 사용량과 SDK 경계 동작.
- 게임 상태 전환·저장 불러오기·모드 비활성화 중 콜백과 대기 명령의 수명 처리.
- 여러 모드가 같은 이벤트나 계산 규칙을 변경할 때 호출 순서와 결과 합성 규칙.
- 게임 버전별 연결 계층과 모드 API 버전 호환성 정책.
- 이미지·음원·설정·저장 데이터가 필요한 모드의 디렉터리 및 소유권 규칙.
- 사용하려는 C# 라이브러리의 trimming/AOT 호환성. 런타임 코드 생성에 의존하는 기능은 별도 검토.

## 연구 재개 시 시작점

이 문서와 `feature_menu.cpp`의 네이티브 버튼 테스트를 먼저 읽는다. 현재 브랜치와 기존 수정사항을 확인한 후, **C# Native AOT 모드 하나가 게임 버튼 클릭을 받아 ImGui를 여는 실험**부터 진행한다. 기존 편집기 전체나 게임 로직 전체를 한 번에 C#으로 옮기지 않는다.
