# UI 이미지와 게임 원본 대응표 — 2026-11-01

## 범위와 근거

현재 `src/proxy/resources.rc`가 내장하는 UI 아틀라스 5장과 범위 이미지 11장을 대상으로 한다. `menu_sprites.h`, `notifications.cpp`의 사용 좌표를 기준으로 작성했다. 작업 중인 창 크기·폰트 변경과 별개로 현재 이미지와 원본의 관계를 기록한다.

설치 경로 `C:\Program Files (x86)\Steam\steamapps\common\SAN8R`의 `0002/root.rdb`·`root.rdx`에서 리소스 ID를 조회하고, FDATA를 읽어 G1T를 디코딩했다. PNG와의 비교는 같은 크기의 RGBA 바이트 전체를 대상으로 한다. 게임을 실행해 화면을 비교한 결과는 아니다.

- [파일별 대응 및 해시 CSV](UI_Resource_Assets_2026-11-01.csv): 18행. 사용 중인 16개 이미지와 미사용 파일 2개.
- [상태별 좌표 CSV](UI_Resource_Sprites_2026-11-01.csv): 48행. 현재 좌표와 원본 해상도 좌표를 함께 기록.
- [인게임 화면 재현을 위한 추가 분석](UI_InGame_Additional_Analysis_2026-11-01.md): 제목 장식·한국어 붓글씨·목록·정보 카드 등 추가 원본과 배치 기준.

좌표는 `[left, top, right, bottom)`이고, G1T 이미지 번호는 **0부터 시작**한다. 파일명 중 `74a9de1537` 같은 10자리 식별자는 뷰어의 출력 위치 식별자이며 게임 리소스 ID로 사용하지 않는다.

### 축소된 compact_controls

원본 이미지는 4096×2048, mip 1개다. 현재 2048×1024 PNG는 원본 mip을 그대로 선택한 파일이 아니다. 원본을 BOX 방식으로 절반 축소해 비교했을 때 채널별 평균 절대 오차는 R 0.341, G 0.368, B 0.272, A 0.021/255였다. 이 값은 그림의 대응을 뒷받침하지만 현재 PNG를 만든 정확한 축소 방식을 확정하지 않는다.

직접 로딩 시 원본 픽셀 좌표는 현재 좌표의 **2배**다. 정규화 UV는 `현재 좌표 / 현재 크기 = 원본 좌표 / 원본 크기`로 동일하다. 이미지의 실제 크기만 4096×2048로 교체하고 현재 픽셀 좌표를 그대로 사용하면 다른 영역을 읽는다. Nine-slice의 화면상 모서리 폭은 현재 논리 크기를 유지해야 한다.

## 직접 로딩 전환 시 필요한 작업

1. 지정한 3개 G1T 리소스를 인덱스로 조회하고 컨테이너별로 한 번 읽고 해제한다.
2. 선택한 이미지의 BC3 크기·데이터 범위를 파싱해 기존 5개 슬롯에 게시한다.
3. compact 이미지의 2배 원본 좌표와 현재 논리 크기 관계를 반영한다.
4. 알림의 fade, 버튼 문구, 아이콘 합성, nine-slice는 현재 렌더링 코드를 사용한다.
5. 범위 이미지 11장은 별도로 유지한다. 미사용 이미지 두 장은 전환 입력에 넣지 않는다.

이 문서는 파일·코드·정적 디코딩 비교 결과다. 빌드·자동 테스트·게임 실행은 하지 않았다.
