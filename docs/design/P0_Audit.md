# P0 완료 조건 중간 대조

설계 18절의 P0 요구는 빌드 입력, 매크로·스레드·hook·설정·자원 목록과 기능 보존표이며 통과 조건은 실행 경로·출처·스레드 소유자 확인이다. 현재 상태를 항목별로 구분한다. 이 표는 P0 완료 선언이 아니다.

| 항목 | 현재 근거 | 남은 일 |
|---|---|---|
| 기준 소스 | 두 참고 저장소의 고정 커밋과 clean 상태 확인 | 기준이 바뀌면 모든 목록 재평가. |
| 빌드 입력 | [프로젝트 목록](P0_Build_Inputs.md), 이 PC의 x64·Win32 각 6개 구성 평가와 포함 파일 후보 | 전처리 분기·컴파일러 암묵 입력, 링크 결과 및 배포물을 실제 빌드 없이 확정할 수 없다. 사용자 지시에 따라 빌드하지 않았다. |
| 매크로 | `p0/source_locations.csv`의 도달 파일 텍스트 색인, 주요 wrapper 수동 추적 | 조건부 활성 여부 및 나머지 동작 치환의 실행 경로를 모두 확인하지 않았다. |
| 스레드 | [작업 목록](P0_Workers.md), [시작·종료](P0_Lifecycle.md) | 텍스트 검색 외 생성 경로와 callback의 실제 스레드·수명은 검증되지 않았다. |
| hook·패치 | [전투](P0_War_Patches.md), [책략](P0_Stratagem.md), [기능 보존표](P0_Feature_Contracts.md) 및 위치 색인 | 모든 직접 패치, hook 묶음, 실패·복구 및 callback 수명을 확인하지 않았다. |
| 설정 | [설정 계약](P0_Config.md), 기본·추가·숫자 필드 목록 | 고정 wrapper 키와 전기·지형 키의 초기값·처리 범위는 정리했다. 실제 파일 로드·적용과 비설정 기능의 경로는 더 확인해야 한다. |
| 자원·출처 | [자원](P0_Resources.md), [출처](P0_Proxy_Origin.md), 파일 비교. 내장 Ruda Bold는 Google Fonts의 2015년 공개 파일과 바이트가 일치한다. | 실제 도입 경로, 다른 자산의 원출처와 전체 고지는 미확인이다. 상류 후보와의 차이만으로 도입 커밋을 확정하지 않는다. |
| 기능 보존표 | 주요 UI·전투·기재·무장·전기 경로와 회귀 조건 | 모든 기능별 동작이 망라되지 않았다. 표의 회귀 조건은 실행 결과가 아니다. |

P0의 나머지 조사에 사용할 직접 소스 위치는 `p0/` CSV에 기록되어 있다. 안전한 게임 쓰기 문맥, hook quiescence, IME·장치 전환 등은 실제 호스트에서 근거를 얻기 전 이관 완료로 취급하지 않는다.

## 설정 키와 조사 문서 대조 후보

[설정 키 문서 대조 후보](p0/config_document_candidates.csv)는 기본 설정 62개와 wrapper의 고정 키 36개에 대해 조사 문서에서 동일한 키 문자열이 나타나는 위치를 기록한다. 공통 설정 설명·목록·감사 문서는 검색에서 제외했다. 기본 키 중 47개, wrapper 키 중 21개에서 문자열이 발견됐다. 이는 문서의 기능 설명이 충분하거나 실행 경로가 검증됐다는 뜻이 아니다. 나머지는 기능명이나 다른 식별자로 이미 조사됐을 수 있으므로 누락으로 단정하지 않는다. 각 후보를 원본 소스의 호출 경로와 대조해 기능별 근거와 미확인 상태를 확정해야 한다. 생성형 전기 키와 지형 키, 별도 경로 파일은 이 색인의 범위 밖이다.

## 최근 대조 및 우선 미확인 범위

현재 기준 커밋과 두 참조 저장소의 변경 없음 상태를 다시 확인했다. x64 활성 소스의 파일 존재, 13개 선언 자원의 존재와 해시, 여러 전투·도시·설정 기능의 소스 경로가 추가됐다. 이에 따라 문자열 색인은 갱신했지만 문자열의 존재만으로 기능별 완료를 판정하지 않는다.

- 빌드 입력: x64 6개 구성의 평가와 파일 존재는 확인했다. Win32 6개 구성 평가를 추가했다. 실제 전처리·링크·배포 입력은 확인하지 않았다. 빌드는 사용자 지시에 따라 수행하지 않는다.
- 실행 경로와 소유자: 메뉴·background loop·게임 callback의 정적 호출 주체는 다수 구분했다. 게임 callback의 실제 스레드, 세대 변경과 종료 중 동작은 여전히 검증되지 않았다.
- 출처: 포함 라이브러리의 기준 저장소 비교와 파일 고지를 조사했으나 정확한 상류 revision과 이미지·폰트 출처는 확정되지 않았다.
- 기능 보존: 도시 관리와 추가 설정을 확장했으나 전체 메뉴·hook에 대한 일대일 보존 계약과 근거 대조는 남아 있다. 매크로 치환과 조건부 코드도 전부 추적하지 않았다.

이 항목들이 남아 있어 P0를 완료로 표시하지 않는다. 게임 실행이나 빌드가 필요한 사실과 정적 조사만으로 아직 더 확인할 수 있는 부분은 구분해 진행한다.

## 조사 문서 중복 정리

기능 보존표의 평정 이동·재야 처단과 상성 표시 항목을 각각 한 곳으로 합쳤다. 설정 기본값, 코드 공간 크기, 미확인 동작 및 화면 전환 조건을 기존 항목에 보존했다. 앞의 설정 키 문자열 대조 CSV는 이 정리와 최근 추가 조사 이전에 생성된 후보 목록이므로 현재 누락 건수로 사용하지 않는다. P0의 미조사 범위와 실제 실행 문맥 확인은 그대로 남아 있다.

## 설정 키 색인 재대조

현재 기능별 조사 문서를 대상으로 [갱신된 문자열 대조 후보](p0/config_document_candidates_current.csv)를 별도로 생성했다. 기본 키 62개 중 47개, wrapper 고정 키 36개 중 24개의 정확한 키 문자열이 검색된다. 공통 설정 설명·목록·감사 문서는 기존 색인과 같이 제외했다. 일치하지 않는 항목도 기능명이나 묶음 표현으로 이미 기록된 경우가 있다. 예를 들어 `bFileLog`는 설정·worker 문서에서, `bReinforcementArrivalAction`은 원군 즉시 행동으로, 책략 숫자 키는 책략 세부 설정으로 조사돼 있다. 반대로 키가 나타나더라도 기능 계약의 완전성을 증명하지 않는다. 이 CSV는 수동 검토를 위한 위치 색인이며 P0 통과 집계가 아니다.

## 추가 근거와 현재 확인 범위

- [빌드 입력](P0_Build_Inputs.md): 솔루션 기반 읽기 전용 평가에서 플랫폼 미지정 시 이 환경의 기본은 x64다. 세 프록시의 Release 중간 경로도 개별 확인했다. 컴파일러 실행과 최종 바이너리 확인은 하지 않았다.
- [프록시와 출처](P0_Proxy_Origin.md): 공식 ImGui WIP 후보·Kiero 공개 이력, 현재 Windows 시스템 DLL과 게임 폴더 기존 hid의 이름·ordinal을 대조했다. 설치된 게임의 정적 의존성 후보는 실제 로더 선택을 증명하지 않으며 정확한 라이브러리 도입 경위와 자산 출처도 미확인이다.
- [실행·종료](P0_Lifecycle.md), [직접 패치](P0_War_Patches.md): 친밀도 진단 등 직접 hook은 공통 MinHook 종료와 별도로 추적해야 한다. 게임 파일의 선택 RVA 서명은 파일 바이트로 확인할 수 있었으나, 실행 메모리와의 동일성이 입증되지 않아 실제 버전 적합성은 미확인이다.
- [설정](P0_Config.md), [리소스](P0_Resources.md): 현재 설치된 파일을 읽기 전용으로 대조했다. 독립 군주 제안 키의 저장 차이와 설치된 기재 파일·외부 `version.dll`의 존재를 확인했지만 설치된 바이너리의 실제 적용 결과는 확인하지 않았다.
- [책략](P0_Stratagem.md), [기능 보존](P0_Feature_Contracts.md): 5번 책략 추가 회복의 전의 변화 기반 판정, 위젯 표시 조건과 적극 성향·능력치 보정의 게이트를 추가했다. 각 내용은 정적 소스의 실행 경로이며 실제 게임 결과가 아니다.

각 목록의 확인은 해당 범위의 근거다. 전체 기능의 경로·스레드와 외부 자산 출처, 실행 시 패치·자원·종료 결과가 아직 남아 있으므로 P0 완료 조건으로 집계하지 않는다. 빌드와 게임 실행은 하지 않았다.

## 기능 소스와 조사 문서의 파일명 대조

x64 여섯 구성의 평가 항목 중 제외되지 않은 `Cheats` 아래 소스 86개를 기준으로, 빌드 목록·목차·감사 문서를 제외한 P0 문서에 파일명이 등장하는지 대조한 [후보 목록](p0/feature_source_document_candidates.csv)을 만들었다. 최초 대조에서 82개는 파일명이 발견됐고 4개는 발견되지 않았다. 일치는 해당 파일의 모든 실행 경로를 확인했다는 뜻이 아니며, 미발견도 기능명으로 조사했을 수 있다.

미발견 중 `SkillCountManager.cpp`의 파일 저장·종료 경로는 이미 [리소스 조사](P0_Resources.md)의 무장 전법·특수능력 수치 파일 절에 기록돼 있었다. 나머지 세 파일의 설치와 복구는 [특기 보기 조사](P0_Trait_Viewer.md)의 개별 복구 절에 추가했다. CSV는 이 보강 직전 대조 결과를 보존한 위치 색인이며 완료율이 아니다. 헤더·inc, `Cheats` 외 자체 소스, Win32 전용 분기, 전처리 결과와 실제 호출 스레드는 이 비교에 포함되지 않는다.

## 메뉴 조작 텍스트 후보

최상위 `Menu_impl.inc`, `MenuSections*.cpp`, `TacticsEditWindow.cpp`에서 ImGui 조작 호출과 문자열 리터럴이 같은 줄에 있는 항목을 [후보 목록](p0/menu_control_candidates.csv)으로 추출했다. 이 범위의 텍스트 일치는 체크박스 75, 버튼 41, 정수 입력 33, 정수 슬라이더 11, 실수 슬라이더 4, 콤보 2로 총 166건이다. 주석과 조건부 코드가 섞일 수 있으며 여러 줄 호출, 변수·동적 label, wrapper, 다른 창 소스와 게임 내부 UI는 이 방식에서 빠진다. 각 항목의 정확한 label이 P0 기능 문서에 있는지도 후보 위치를 표시했지만, 이름이 없다고 미조사라고 단정하지 않고 이름이 있어도 기능 계약 완성을 뜻하지 않는다.

예를 들어 임무 총 임명 한도의 원본 복구 버튼은 문서에 버튼의 전체 ImGui ID 문자열은 없지만 [기능 보존표](P0_Feature_Contracts.md)의 임무 항목에서 호출과 복구 조건을 추적했다. 5번 책략 설정 팝업의 편집과 취소는 [책략 조사](P0_Stratagem.md)에 추가했다. 나머지 후보는 실행 경로 및 결과를 원본과 수동 대조해야 한다.

## MinHook 대상별 정적 목록

[MinHook 대상과 정적 소유 목록](P0_MinHook_Inventory.md)에 직접 등록 표기, 공통 wrapper와 반복문의 대상, 설치 요청 조건 및 현재 확인된 정리 경로를 합쳤다. 호출 스레드는 게임/API가 호출하는 문맥으로만 적었으며 실제 스레드 ID와 callback 종료는 여전히 미확인이다. 직접 패치·WndProc·라이브러리 내부와 동적 호출은 표에서 별도 범위로 둔다.

## 설정 키 후보의 현재 문서 재대조

최근 추가된 조사 기록을 포함해 [최신 키 문자열 후보](p0/config_document_candidates_latest.csv)를 생성했다. 기존 후보와 같은 62개 기본 키·36개 wrapper 고정 키를 대상으로, `P0_Audit.md`, `P0_Config.md`, `P0_Inventory.md`를 제외한 P0 문서에서 PowerShell `Select-String -SimpleMatch`로 찾았다. 대소문자를 구분하지 않는 부분 문자열 검색이다. 기본 키 53개와 wrapper 키 26개에서 문자열이 나왔고, 각각 9개와 10개에서는 나오지 않았다.

이 숫자는 기능별 조사 완료율이 아니다. 키가 없는 경우도 기능명·설명 또는 묶음으로 이미 기록됐을 수 있다. 예를 들어 치료 단계 키는 `P0_Traits`가 아니라 기능 보존표의 치료 전법 설명으로 조사했고, 책략 숫자 키는 책략 설정값 묶음으로 기록돼 있다. 반대로 문자열이 있다고 메뉴·실행·종료 계약이 완성됐다는 뜻도 아니다. 생성형 키와 이 두 목록 밖의 기능은 조사 범위에 넣지 않았다.

## 직접 점프 호출의 함수 연결 상태

`ApplyJmp`의 텍스트 직접 호출 24곳은 [직접 패치 조사](P0_War_Patches.md)의 책략 슬롯 10곳과 그 밖의 14곳 표에서 각각 설치 함수·기능으로 연결했다. 호출 크기는 [별도 CSV](p0/applyjmp_call_sizes.csv)에 있다. 예를 들어 공격·수비 게이지의 공용 cave는 [책략 조사](P0_Stratagem.md#공격수비-책략-게이지-hook의-실제-쓰기와-소유)에 메뉴·설정·게임 쓰기 및 실패 후 수명을 기록했다.

이는 해당 이름을 사용하는 직접 호출의 정적 대응이다. 다른 방식의 코드 쓰기, 간접 호출, 실제 callback 스레드와 종료 시 실행 완료까지 확인한 것은 아니므로 전체 hook 항목 완료를 뜻하지 않는다.

## 조사 자료 연결 확인

## 최근 조사와 근거 재확인

기준 S8RPKCheats의 HEAD는 `068ca1d881edf870f7cf06f935cf50e286004af8`이고 작업 트리 변경은 없다. 현재 P0 문서의 Markdown 로컬 링크에서 파일 대상은 모두 존재한다. 링크 검사는 절 제목이나 문서 내용의 완전성을 증명하지 않는다.

최근에는 [무장 편집](P0_Officer.md)의 전법·특기 64개 화면 항목, 두 상세 창의 snapshot과 다중 선택 주소 캐시를 조사했다. [직접 패치](P0_War_Patches.md)에는 공통 `RestoreBytes` 호출 14곳(legacy 1곳 포함), 설치·복구 크기 짝 12개와 복구 뒤 명령 캐시 처리 차이를 보강했다. [시작·종료](P0_Lifecycle.md)에는 Present hook 생성 실패와 재시도 범위, 즉시 경애 직접 패치의 종료 경로를 추가했다.

이들은 위 요구를 좁은 범위에서 보강한 근거다. 기능 전체의 일대일 보존 계약, 조건부 컴파일의 실제 결과, 모든 callback의 스레드·수명, 일부 자원 출처와 실제 빌드 입력은 여전히 완료로 판정하지 않는다. 빌드와 게임 실행은 수행하지 않았다.

스레드 생성 API의 추가 텍스트 검색에서는 외부 `Framework`·`Hooking`을 제외한 자체 cpp·h·inc에서 `_beginthreadex` 외에 `_beginthread`, `QueueUserWorkItem`, `CreateThreadpool*`, `SubmitThreadpoolWork`, `std::async`, `CreateRemoteThread`, `CreateTimerQueueTimer`의 표기를 찾지 못했다. `_beginthreadex`는 기존 [파일 로그 worker 조사](P0_Workers.md)에 연결돼 있다. 이 결과는 함수 포인터·외부 라이브러리·조건부 전처리 결과까지 배제하지 않는다.

`p0/`의 CSV 53개는 모두 PowerShell `Import-Csv`로 읽혔다. 이는 형식상 읽기 확인이며 각 행의 출처나 완전성을 검증한 것은 아니다.

### 후속 조사 대조

이 대조 당시 P0 문서 19개와 CSV 60개가 있었다. 건수는 조사 범위나 완료율이 아니다. [기능 보존표](P0_Feature_Contracts.md)에 상극 hook의 분기·주소 캡처, 일괄 기재 배정의 객체 검색·주소 수명, 후방지원과 군단 자동배치의 렌더·background 공유 상태를 보강했다. [출처 비교](P0_Proxy_Origin.md)에는 공식 MinHook v1.3.3 파일·토큰·지시문 대조를, [자원](P0_Resources.md)에는 바이트가 같은 공개 Ruda Bold와 해당 고지를 연결했다. S8RPKCheats 기준 저장소의 `git status --short`는 출력이 없다.

위 결과는 정적 조사다. 남은 P0 통과 조건은 전체 기능의 실행 경로와 소유자, 직접·간접 패치의 설치·복구, 실제 빌드 입력과 미확정 자산 출처를 각각 근거와 대조하는 것이다. 빌드·게임 실행은 사용자 지시에 따라 하지 않았으므로 실행 중 callback 스레드와 실제 전처리·링크 결과는 확인하지 못했다. P0를 완료로 표시하지 않는다.

최근 추가된 MinHook v1.3.3 파일 비교표의 14쌍 SHA-256을 현재 기준 소스 및 공식 후보 체크아웃에서 다시 계산해 모두 일치시켰다. 후보 HEAD는 `9fbd087432700d73fc571118d6a9697a36443d88`, 기준 HEAD는 `068ca1d881edf870f7cf06f935cf50e286004af8`이다. P0 Markdown의 로컬 파일 링크 대상도 재검사해 누락이 없었다. 이 검사는 파일 해시와 링크 경로에 한정하며 토큰 분석의 완전성, 절 anchor, 실행 동작 또는 위 미완료 조건을 증명하지 않는다.

| 게임 식별 | 설치 파일의 CodeView GUID·age는 주기 코드 기대값과 일치한다. | 로드된 이미지의 검사 결과와 실제 호출 시점. |
| 캡처 및 필터 설치 | 같은 파일에서 캡처 고정 RVA와 필터의 다섯 RVA 바이트가 기대값과 다르며 캡처 패턴은 파일 전체에서 발견되지 않았다. | 로드된 메모리의 서명·fallback 결과와 실제 설치. |
| 요청과 후보 제한 | 주기 요청은 필터 설치 성공을 조건으로 검사하지 않는다. | 필터 실패 시 실제 게임의 후보 선택 결과. |
| OFF·종료 | 자동 발생 OFF, 직접 캡처 복구, MinHook 해제, 기간·쿨다운 복원은 서로 다른 경로다. | 실행 중 콜백 완료와 게임 데이터의 실제 복원. |

파일 바이트와 정적 호출 관계의 상세는 [전기 조사](P0_Tengi_Ronin.md#전기-캡처와-주기), 종료 경계는 [시작·종료 조사](P0_Lifecycle.md#전기-필터와-데이터-복원의-종료-경계)에 있다. 이는 P0 완료 판정이나 실행 검증이 아니다.
## 무장 ID와 주소의 이관 대조

| 기존 경로 | 중복·세대 처리 | 이관 시 확인 |
|---|---|---|
| 전체 목록 | 유효한 상태 주소까지 확인한 뒤 ID 중복을 표시한다. | 동일 ID의 앞 슬롯 읽기 실패, 목록 구축 중 배열 변경. |
| 다중 수치 편집 | 선택 ID에서 주소 캐시를 만들며 배열 변경 시 주소 캐시는 비우지만 ID 선택은 남는다. | 새 배열에서 주소 재구축 전 편집과 재선택. |
| 선택 무장 재야 전환 | 주소 캐시 대신 선택 ID로 현재 배열을 다시 순회한다. | 같은 선택 배너에서 일반 일괄 편집과 다른 대상 처리. |
| AI 성장 | 대상 여부와 미리보기 전에 중복 ID를 표시한다. | 첫 중복 슬롯이 비대상 또는 읽기 실패일 때 뒤 슬롯 처리. |

상세 코드 경로와 실제 관찰하지 않은 조건은 [무장 조사](P0_Officer.md)를 따른다. 이는 ID가 항상 고유하거나 서로 다른 포인터 체인이 같은 게임 객체를 가리킨다는 증거가 아니다.
## 산출물 형식 재확인

현재 P0 문서 19개에 있는 로컬 Markdown 파일 대상은 모두 존재하며, `p0/` CSV 62개는 PowerShell `Import-Csv`로 읽혔다. 새로 추가한 포인터 기록 후보도 포함한다. 이는 파일 대상과 CSV 읽기 형식의 확인으로, 절 anchor·각 행의 정확성·P0의 전체 실행 경로를 검증한 결과는 아니다. 실제 전처리·링크, 게임 callback 실행 스레드와 일부 자원 출처는 위 표처럼 남아 있다. 빌드·게임 실행은 하지 않았다.
