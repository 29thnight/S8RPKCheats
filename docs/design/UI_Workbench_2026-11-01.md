# 분류형 편집 UI와 독립 ImGui 미리보기

## 변경 목적

기존 화면은 세 열에 모든 설정과 편집창 진입점을 함께 표시했다. 설정 파일을
불러온 상태, 게임에 주인공이 연결된 상태, 개별 패치가 실제 적용된 상태도 같은
화면에 흩어져 있었다. 이번 변경은 왼쪽에서 분류를 선택하고 오른쪽에서 해당
작업을 하는 구성으로 바꾸며, 개요에서 준비 상태와 적용 결과를 따로 보여준다.

게임과 미리보기는 [feature_menu.cpp](../../src/overlay/feature_menu.cpp) 및 기존
편집창 코드를 공유한다. 별도로 그린 목업이 아니며, 미리보기의 데이터 공급부와
SDL 렌더러만 게임 실행 경로와 다르다. 사용자 제공 스프라이트를 실제 위젯에
사용했다.

## 화면 구성

| 분류 | 제공하는 작업 |
|---|---|
| 개요 | 설정 준비, 시나리오·주인공 연결, 공용 무장 목록 조회 상태; 적용 결과 필터와 편집창 바로가기 |
| 무장 | 모든 무장·주인공 편집, 주인공 자원·보주, 무장 정보와 알림 |
| 기재 · 성장 | 기재 이름·설명, 3칸 표시, 일괄 전법·특기·랜덤 기재, 능력치 한계, AI 성장과 특수능력 판정 |
| 도시 · 내정 | 도시 종류·편집, 명품 관리, 도시 관리·후방 지원, 군단 배치·도시 무장 이동, 내정 규칙 |
| 평정 · 교류 | 평정 규칙, 무장 이동 제한, 교류 횟수와 관계 설정 |
| 전투 | 전장 규칙, 전투 환경, 전법·방어 건물, 책략 게이지와 5번 책략 |
| 시나리오 | 군주 보너스, 도로·시나리오 보정, 가족·시나리오 도구, 세력 기술 초기화·미발견 무장 처리 |
| 환경설정 | 위젯·알림·로그·배속·UI 배율·시작 설정, 메모장·메모리 도구 |

페이지마다 스크롤 위치와 popup ID 범위를 유지한다. 설정 팝업이 열린 동안에는
분류 이동을 막아 팝업을 그리는 코드가 사라지지 않게 한다. 화면을 축소하거나
배율을 높이면 창 크기와 위치를 작업 영역 안으로 보정한다. 큰 배율에서 콘텐츠가
작업 영역보다 넓으면 내부 스크롤을 제공한다.

주인공 전용 편집은 주인공이 있어야 사용할 수 있다. 공용 무장 목록과 기재 등
별도로 조회하는 편집창의 진입점은 그 조건과 분리한다. 실제 게임의 각 테이블이
아직 준비되지 않았다면 해당 편집창의 조회 상태를 확인해야 한다.

## 준비 상태와 적용 결과

개요 상단의 세 상태는 독립적이다.

1. **설정 불러오기:** 설정 스냅샷이 UI에 도착했는지 표시한다.
2. **시나리오 · 주인공:** 주인공 연결, 주소 검색 진행률, 자동 재검색, 메모리 읽기
   실패를 구분한다.
3. **공용 무장 목록:** 현재 세대의 목록에 대해 미조회·조회 중·조회 완료와 수를
   표시한다. 이전 세대의 데이터를 새 조회 완료로 표시하지 않는다.

적용 현황은 `ConfigSnapshot`이 제공하는 native 11개 그룹, legacy 27개 그룹,
기재 관련 3개 항목을 대상으로 한다. 모든 체크박스와 게임 메모리 쓰기를
전수 검증한 개수가 아니다.

| 표시 | 판단 근거 |
|---|---|
| 적용 확인 | 해당 그룹 또는 기재 런타임이 `Applied`로 보고한 경우 |
| 대기 | 요청 대기, 주인공 준비 대기, 기재 테이블·callback·live object 대기 |
| 확인 필요 | native 실패·불확실, legacy 재시도, 기재 적용·복구 오류 |
| 외부 관리 | 확장 기재를 외부 런타임이 관리한다고 보고한 경우 |
| 꺼짐 | 해당 기능군의 상태가 비활성인 경우 |

체크 표시는 사용자가 원하는 설정이며 적용 성공과 동일하지 않다. `applied`
불리언이 남아 있어도 현재 phase가 `Pending`이나 `Failed`이면 성공으로 집계하지
않는다. 기본 필터는 대기·오류·외부 관리만 보여 주고, 항목을 누르면 관련 설정
페이지로 이동한다.

## 제공된 스프라이트 사용

10개 시트를 확인하고 필요한 세 장을 원본 바이트 그대로 복사했다. 색상 변환,
배경 제거, 잘라낸 PNG 생성은 하지 않았다. 런타임에서 UV로 영역을 선택하고
버튼과 패널의 모서리를 보존하는 nine-slice로 늘린다. 아래 상태 매핑은 제공된
메타데이터가 아니라 이미지의 외관을 보고 이번 UI에 지정한 것이다.

| 제공 파일 끝부분 | 저장소 파일 | 크기 | 리소스 ID | 사용 |
|---|---|---|---|---|
| `027(1).png` | `resources/ui/menu_controls.png` | 1024 × 512 | 301 | 분류 버튼, 목록·무장·기재·도시·설정 아이콘 |
| `032.png` | `resources/ui/status_badges.png` | 1024 × 512 | 302 | 준비·대기·실패·외부 관리 배지 |
| `033.png` | `resources/ui/panel_frame.png` | 2048 × 2048 | 303 | 본문 배경과 테두리 |

좌표는 `[left, top, right, bottom)`이다. 전체 아이콘 좌표와 상태별 선택은
[menu_sprites.h](../../src/overlay/menu_sprites.h)에 있다.

| 영역 | 좌표 | 모서리 보존 폭 |
|---|---|---|
| 기본 버튼 | `(54, 236, 186, 284)` | 12 × 10 |
| hover 버튼 | `(188, 236, 320, 284)` | 12 × 10 |
| 선택된 버튼 | `(322, 236, 454, 284)` | 12 × 10 |
| 눌린 버튼 | `(456, 286, 588, 334)` | 12 × 10 |
| 비활성 버튼 | `(54, 286, 186, 334)` | 12 × 10 |
| 준비 배지 | `(776, 241, 922, 279)` | 16 × 8 |
| 대기 배지 | `(774, 198, 924, 238)` | 16 × 8 |
| 오류 배지 | `(480, 247, 628, 285)` | 16 × 8 |
| 외부·비활성 배지 | `(634, 247, 722, 285)` | 16 × 8 |
| 본문 패널 | `(666, 6, 1254, 444)` | 24 × 24 |

PNG의 SHA-256:

```text

status_badges.png 2f86aa323104e360973758283878aad91209115b9c74c0d80f7924bd6c6de877
panel_frame.png d29a1931790e089c19b20de50e45162891b902a126aa1d090c2bd6e42cf88457
```

네이티브 ImGui 버튼이 ID, focus, 키보드·마우스 처리와 비활성 상태를 담당하고,
스프라이트는 그 결과에 맞춰 그린다. 이미지를 불러오지 못해도 같은 위젯 ID와
기본 ImGui 버튼으로 동작한다. 어두운 불투명 배경, 금색 강조와 따뜻한 글자색은
`ThemeScope` 안에서만 적용하고 종료 시 이전 스타일을 복원한다.

게임에서는 설정 서비스 스레드가 WIC로 PNG를 디코드하고 불변 CPU 이미지를
`UiBridge`에 게시한다. Present 스레드가 DX11 텍스처를 만들며, resize·device
재생성·종료 시 UI의 빌린 handle을 먼저 비운 뒤 SRV를 해제한다. CPU 원본이
남아 있어 다음 Present에서 재업로드할 수 있다. 선택적 이미지 실패가 설정
불러오기 자체를 막지 않도록 예외 경계를 분리했다.

## 독립 실행과 검증

빌드 명령, CLI, 샘플 상태, 검증 스크립트는
[tools/preview/README.md](../../tools/preview/README.md)에 있다.

공유 UI 소스를 SDL2·SDL2_image와 함께 컴파일하는 독립 CMake target을 추가했다.
기존 Visual Studio 게임 프로젝트와 설정은 변경하지 않았다. 미리보기는 실제
`UiBridge`와 `CommandMailbox`를 사용하되 `SampleSession`이 응답한다. 게임 프로세스,
게임 메모리, 세이브, 기존 설정 파일에는 접근하지 않는다. 지원하지 않는 게임
명령은 성공으로 흉내 내지 않고 거절·안내한다.

상단에 샘플 데이터임을 표시하고 정상 연결, 타이틀·주인공 없음, 설정 로딩,
일부 대기·실패, 외부 기재 관리 상태를 전환한다. 100/125/150% 배율, 메뉴 다시
열기, PNG 저장도 상단에서 사용할 수 있다. 실제 설정 슬라이더도 조작할 수 있다.

검증 코드는 실제 ImGui 위젯의 위치를 관찰하고 SDL 입력 이벤트를 보내므로
화면과 별도인 가짜 컨트롤을 시험하지 않는다. 테스트 결과가 증명하는 범위는
공유 UI·입력·샘플 명령 처리이다. 실제 게임 주소, 메모리 쓰기, DX11 hook 및
전체 게임 DLL의 성공은 이 검증에 포함되지 않는다.

### 이번 검증 결과

| 항목 | 결과 |
|---|---|
| Linux Debug 독립 UI 빌드 | GCC 13.3, SDL2 renderer로 빌드·실행 성공 |
| Windows x64 Release 독립 UI 빌드 | MinGW 13.2로 PE GUI 실행 파일 링크 성공 |
| Windows 실행 파일 스모크 | Wine64 + Xvfb에서 8프레임 렌더링, 정상 종료, PNG 저장 성공 |
| 공유 UI 시나리오 | 입력 시나리오 10개와 상태 렌더링 4개 통과, assertion 합계 61개 |
| 스프라이트 위젯 테스트 | `sprite_controls` CTest 통과; 별도 Release `-DNDEBUG` 실행도 통과 |
| 코드 대조 | 기존 기능 ID·popup 진입점·명령 payload 종류와 횟수의 누락 없음 |

입력 시나리오는 8개 페이지 이동, 설정 변경과 완료, 주인공 없는 상태의 공용
무장·기재·도시 창, 로딩 중 비활성, 요청 대기 중 중복 입력 방지, 전투 modal,
숫자로 배율 입력, 150%와 창 축소, 상태 전환, 실패 항목에서 해당 페이지로 이동,
atlas 없는 기본 버튼을 확인했다. 창 축소 검사에서 발견한 위치 이탈을 수정하고
같은 검사를 통과했다.

재현 가능한 결과는 `validate.py`가 생성하는 `validation.json`과 사례별 로그,
PNG에 기록된다. Wine 실행은 Windows PE가 호환 환경에서 동작한 검증이며 실제
Windows PC에서 실행한 검증과 구분한다. 전체 게임 DLL 빌드 및 실제 게임 실행은
이번 독립 UI 검증에 포함하지 않았다.

## 변경 및 재컴파일 범위

주요 변경은 `feature_menu.cpp`, `menu_sprites.h`, `ui_atlas.h`, 텍스처 연결을 위한
`overlay_present`·`dx11_overlay`·`runtime_services`·`ui_bridge`, PNG 리소스와 독립
미리보기 소스이다. `FeatureMenu`·`UiBridge`·`Dx11Overlay` 헤더를 포함하는 overlay,
services, runtime 단위는 재컴파일 대상이고 proxy는 새 리소스를 다시 링크해야
한다. 게임 주소와 기능 적용 알고리즘은 이번 UI 변경에서 바꾸지 않았다.

공유 UI 컴파일에서 확인한 기존 `officer_tools_panel.cpp`의 `TextWrapped` 문자열
`0%`는 printf용 `0%%`로 고쳤다. ImGui fork의 custom slider test hook은 현재 코어의
`LastItemData.StatusFlags`를 보고하도록 한 줄 수정했으며, test hook을 활성화하지
않는 게임 빌드의 위젯 동작에는 영향을 주지 않는다.
